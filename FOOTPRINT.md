## Where it installs

`composer require anun333/oe-module-staff-worklist` places it in `interface/modules/custom_modules/oe-module-staff-worklist/` (the `openemr/oe-module-installer-plugin` rule: `custom_modules/` plus the part of the package name after the slash). It changes no OpenEMR core file. Enable it under Modules > Manage Modules.

## What installing it changes in the database

4 statements in `sql/install.sql`, every one classified below. Each sits inside an `#If…` guard (`#IfNotTable`, `#IfNotRow`), so re-running the install changes nothing.

- **Core schema changes:** none.
- **Tables it creates and owns:** `staff_worklist_state`, `staff_worklist_log`, `staff_worklist_caregap_cache`.
- **Rows added to core tables:** `background_services`.
  - `background_services`: one row, `StaffWorklistCareGaps` ("Staff Worklist care gaps"), which runs `staffWorklistRefreshCareGaps()` from `/interface/modules/custom_modules/oe-module-staff-worklist/background/caregaps.php` every 10 minutes. It is installed inactive; the module switches it on when enabled and off when disabled (`ModuleManagerListener.php`).

- **No uninstall script** (`sql/` holds only `install.sql`): disabling or removing the module leaves the tables and rows above in place, along with anything staff recorded in them.
